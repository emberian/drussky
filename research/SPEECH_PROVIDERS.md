# AI teacher speech providers

Checked 2026-11-05. `rufren-speech` provides default machine-generated Russian reference speech without requiring a human recording. A friend’s conversational example can still be imported as an additional voice. Generated models support listening, repetition and comparison; generation provenance does not certify perfect recitation or judge the learner’s pronunciation.

## Provider choices

The primary cloud path is fixed `gemini-3.8-flash-tts` with the prebuilt `Kore` voice. The current official guide lists Russian support and recommends this model when fidelity and difficult pronunciation matter. It separates the verbatim transcript from style instructions, addressing a useful failure mode of older prompt-based TTS. This is a reasoned starting choice from provider documentation, not a comparative Russian listening benchmark. The guide lists 2.5 Pro and 3.1 Flash TTS as older preview options; Rufren does not silently fall back to either. [Official speech generation guide](https://ai.google.dev/gemini-api/docs/speech-generation).

The adapter follows the guide’s REST Interactions request: `POST https://generativelanguage.googleapis.com/v1beta/interactions`, `x-goog-api-key` header, `store:false`, exact text in `input`, fixed Russian delivery in `speech_metadata`, `speech_config` naming Kore, and explicit inline `audio/wav` at 24 kHz. A single completed model output must contain one inline audio block. The gateway validates the RIFF container, mono signed 16-bit little-endian PCM and declared duration, then canonicalizes the WAV. It never follows an audio URI or accepts arbitrary encoded formats. The current guide uses `generation_config.speech_config`, while the generic API reference describes `structured_speech_config`; the implementation follows the TTS-specific REST example. Actual account-backed compatibility still needs a live check. [Interactions overview](https://ai.google.dev/gemini-api/docs/interactions), [API reference](https://ai.google.dev/api/interactions-api).

The optional local path is the installed macOS `Milena` Russian voice, selected explicitly with `RUFREN_SPEECH_PROVIDER=macos`. It runs `/usr/bin/say` without a shell, receives text on stdin, writes WAVE/LEI16/24 kHz/mono to a private operation directory, validates its container and canonicalizes the output. It does not use Gemini or make a speech-provider network request. The inspected Mac lists `Milena ru_RU`. The command contract comes from the system’s `man say` and `say --file-format='?'`; a successful public-fixture generation test is required separately from presence. Other operating systems return a configuration error for this backend. Its provider is `macos_say`, model/voice are `Milena`, and provenance kind is `system_generated_speech`, distinct from Gemini’s `ai_generated_speech`. It has no API-token charges and makes no cloud-quality claim.

## Explicit configuration and transport

Cloud generation requires both `RUFREN_SPEECH_PROVIDER=gemini` and a server-only `GEMINI_API_KEY`. Local generation uses an explicit `RUFREN_SPEECH_PROVIDER=macos`, `qwen` or `local_russian`; the neural paths additionally require their pinned offline installation and prepared Qwen worker. An omitted/disabled selector makes the service explicitly unavailable. Constructors and status reads do not generate speech, inspect billing, harvest CLI/browser authentication, or change accounts. Chat/Gemini subscriptions do not prove an API entitlement. No cloud request or account mutation was made during implementation.

The shared request is `{text, request_id, revision_id?}`. The gateway validates identifiers and short text, sends only the text and fixed delivery settings to Gemini, and echoes exact request/revision/text bindings itself. It does not upload learner recordings, notebook history or request identifiers to the model. The private relay authenticates the caller; app consent describes the selected backend and what leaves the device. The selected macOS backend still receives the text on the relay Mac, even though no external speech service receives it.

A response includes canonical `wav_base64`, exact-byte SHA-256, 24 kHz/mono/frame metadata, source text, bindings, provider/model/voice/prompt version, machine-generation kind, and usage/reservation estimates. The app verifies bindings, WAV shape and hash before storing the original. Store this provenance with the reference asset through local backup and explicit recording sync. An AI/system-generated reference is usable machine teaching material, not a fabricated human or native-speaker recording.

## Bounds and costs

Text is capped at 1,024 UTF-8 bytes and 256 characters. It must contain alphabetic content; control characters, inline angle-bracket vocal tags and macOS embedded speech commands are rejected. Provider requests are capped at 8 KiB, HTTP JSON responses at 4 MiB including chunked bodies, and decoded PCM at 45 seconds. Wrong format/rate/channels/model, incomplete responses, extra model outputs, text/tool returns, malformed base64, odd or empty PCM and all-zero PCM fail explicitly. These structural checks cannot prove the spoken text or stress is right.

The server admits one generation at a time with no queue or automatic retry. Gemini has a 5-second connect limit and a 45-second total operation deadline. The local child has a 30-second operation deadline, a tracked PID and bounded validated output; cancellation drops its exact owned process handle. Completed/failed operations remove only their own named output files after the child stops. A canceled local request may leave its private operation directory for inspection, rather than deleting files while a child might still have them open.

`RUFREN_SPEECH_MAX_REQUESTS` defaults to 40 and accepts 1–1,000. Cloud `RUFREN_SPEECH_SESSION_BUDGET_MICRO_USD` defaults to 1,000,000 ($1), accepts 1–5,000,000, and reserves 24,576 microdollars per admitted request: a conservative 4,096-input/1,024-output token allowance at $1/$20 per million tokens. The request sets `max_output_tokens=1024`; reported token counts are bounded, and usage is an estimate when present. Missing usage stays unknown. Failed or canceled cloud operations keep reservations because generation may already have been charged. Clones share process limits; restart resets them. These are application reservations, not persistent billing/account guarantees or measured credits. Local system generation reserves zero money while retaining the request/concurrency limits.

The published standard 3.8 rates are $0.50 input/$9 audio output per million tokens through 2026-12-31, then $1/$18 from 2027-01-01. The implementation deliberately uses higher estimate rates. Free-tier data-use terms differ from paid-tier terms, and actual project/billing configuration must be checked privately before using personal text. [Official Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [billing setup](https://ai.google.dev/gemini-api/docs/billing).

## Local neural follow-on and exact text frontend

The explicit server selector `RUFREN_SPEECH_PROVIDER=qwen` now has a source-integrated local full-BF16 provider. It uses a private authenticated IPv4-loopback worker, pinned `mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16@7d3824abff87e49756bb0f83fb5411de75d160c4`, `mlx-audio==0.6.4`, a versioned designed Russian voice and seed 42. No human voice reference or cloning is involved. Its 4,520,194,992-byte artifact was downloaded into the task-owned `.local/qwen3-tts/` installation and all 14 files were SHA-256 checked, including published LFS hashes. Runtime checks pin identity and file sizes without performing another full multi-gigabyte hash pass. Model weights use Apache-2.0 and the MLX runtime uses MIT. [Upstream Qwen model](https://huggingface.co/Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign), [MLX artifact](https://huggingface.co/mlx-community/Qwen3-TTS-12Hz-1.7B-VoiceDesign-bf16), [MLX implementation](https://github.com/Blaizzy/mlx-audio/blob/main/docs/models/tts/qwen3-tts.md).

The gateway reads only a private server-side `RUFREN_QWEN_WORKER_TOKEN_FILE` (default `.local/qwen3-tts/worker.token`) and loopback port `RUFREN_QWEN_WORKER_PORT` (8790). It never starts or downloads a model from an app request. `checked_status()` checks the `rufren-qwen-worker-v2` contract and readiness; synchronous configuration status does not guess that the worker is ready. An explicit operator preparation precedes activation. One persistent inference thread owns MLX model/streams; requests never queue behind another generation. Normal work has a 50-second soft deadline inside that owner, a 53-second owned-process watchdog and a 55-second gateway-client deadline, fitting the relay's 60-second envelope. Admission remains held until the actual job finishes; a native hang cannot be abandoned with the GPU job still consuming work. Operator preparation has separately bounded longer startup limits. The main private relay now runs the accepted local Russian router after a coordinated configuration/restart and successful HTTPS status checks. Qwen also passed a disposable full UI generation, playback, reload and offline replay. Milena remains an explicitly selectable baseline provider.

Initial public-fixture preparation took 62.137 seconds, with an approved warm repeat taking 19.973 seconds for the same 13.36-second WAV. A later explicit preparation after restart took 21.148 seconds for a 15.84-second ordinary-spelling fixture. Peak process RSS was approximately 4.80 GB and peak Metal memory 5.14 GB on this M2 Max. These are observed resource/latency figures for these fixtures, not a quality ranking or a latency guarantee for every allowed text.

A controlled frontend check exposed a reason to keep source and synthesis inputs distinct. With combining acute marks on the two contextual `замок` tokens, independent ASR heard lexical anomalies. Removing only U+0301, keeping `Всё`, punctuation, seed and voice settings fixed, removed those particular anomalies. This supports ordinary-spelling input for this Qwen case; ASR does not establish the intended lock/castle vowel stress, ё production or naturalness. The marked and unmarked audio remain audit artifacts, not certified stress references.

`source_text` therefore stays exactly bound to the authored request. Optional `provenance.synthesis_input` contains `source_text_sha256`, actual `synthesis_text`, `synthesis_text_sha256`, the declared `transform`, and a `context` category. Legacy Milena/Gemini responses omit the field. Qwen ordinary text is verbatim. Its conservative marked-input policy requires a full contextual text shape, valid post-vowel marks, and no known homograph or repeated base with different stress; short marked phrases and stress contrasts fail actionably before inference. A category such as `contextual_utterance` is a heuristic input category, never verified semantic disambiguation. `SpeechSynthesisInput::validate_for(source_text)` checks the hashes, bounds and exact declared operation in shared Rust/WASM. In particular, it rejects silently changing `ё` to `е` or stripping marks from isolated «Это за́мок.» / «Это замо́к.» references. This is preservation of the intended exercise, not a requirement for a human recording.

A separate official Silero `v5_6_ru` comparator was acquired in `.local/silero-tts/`, pinned to SHA-256 `04cc9b1d08ce38bcaa9d02c488d80d3e6806d17f7eaa7c95982f36a3cbf50b2e` (147,664,410 bytes), with an isolated PyTorch runtime. The model license is CC-BY-NC-SA-4.0, unlike the separately licensed CIS base models. Its documented explicit stress syntax moves the mark before its vowel: authored «Это за́мок.» becomes model input «Это з+амок.», and «Это замо́к.» becomes «Это зам+ок.». All auto-accent/homograph/ё rewriting flags were disabled for the single approved pair. Shared provenance uses `pedagogical_acute_to_silero_plus` / `explicit_stress` and validates that exact shift. Both generated WAVs and source/actual-input/hash sidecars are retained under `.local/silero-tts/samples/`; the CPU-only model loaded in 2.603 seconds, the pair synthesized in 0.995 seconds, and peak RSS was approximately 819 MB. No correct acoustic stress is inferred from successful generation or distinct hashes. ## Explicit local Russian routing

`RUFREN_SPEECH_PROVIDER=local_russian` selects the versioned `rufren-local-russian-v1` strategy, with no app or response-schema change. It decides before inference: authored U+0301 stress goes to Silero with the exact before-vowel `+` transformation and all five automatic accent/ё/homograph/single-vowel controls disabled; ordinary full utterances with at least eight Russian word tokens and a sentence ending go verbatim to Qwen; other ordinary short text goes to Silero with those five automatic controls explicitly enabled and recorded. This input-shape rule does not prove semantic disambiguation or a quality advantage. Known unmarked homographs in short/noncontextual text fail actionably before model access or request allowance consumption, asking for the intended stress or a full sentence. Literal `+` control input is not accepted as authored text.

Each response retains the actual leaf provider/model/voice, exact source and synthesis-input hashes and transformation. Silero's model identity includes the artifact SHA and pinned source repository revision. Its automatic frontend is a declared model choice; the supplied API text is recorded verbatim, and internal automatic rewriting flags are recorded separately in provenance. Peak amplitude, full-scale and conversion-clipping observations are retained in validation text; these are signal observations, not pronunciation grades. There is no error-triggered provider substitution. A selected engine's failure is returned directly.

The fixed Silero runtime lives under this build tree's `.local/silero-tts/`; no request chooses an executable, path or model, performs a download, or supplies a human voice reference. Its one-shot CPU process uses two numerical threads, a 30-second CPU limit, a 35-second caller deadline, 8 KiB stdin, 4 MiB stdout and 64 KiB stderr bounds. A supervisor keeps its own one-operation admission until its exact child is killed and reaped on timeout or cancellation. It leaves no abandoned model job when a caller drops. Every operation checks the full 147 MB model SHA before loading; readiness checks file sizes and manifest identity without model loading. The hybrid readiness gate additionally requires Qwen's prepared warm worker. Installation/checking alone does not certify audio stress.
